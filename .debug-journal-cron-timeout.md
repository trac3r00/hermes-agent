## Findings

## Root cause (confirmed 2026-07-13)
- Mechanism: `cron.scheduler.run_job()` resolves the inactivity limit exclusively from `HERMES_CRON_TIMEOUT`, defaulting to 600 seconds, even though it already receives the complete job record. The live `kalshi-calibration-daily` job therefore failed at 601 seconds with a 600-second limit and cannot extend only its own idle window.
- Evidence: live job `33da5c1f1e49` has `last_error="TimeoutError: Cron job 'kalshi-calibration-daily' idle for 601s (limit 600s) — last activity: initializing"`; `cron/scheduler.py:3085-3097` reads no job field.
- Toggle proof: the focused regression test requires `{"timeout": 1800}` to resolve to 1800 while `HERMES_CRON_TIMEOUT=600`; current code cannot import the resolver and fails before the job value can be honored.
- Fix scope: `cron/scheduler.py` plus focused timeout tests.
